# 0001 — 三层相关性防线（覆盖率闸门 + 协调因子 + Cross-encoder 精排闸门）

日期：2026-06-11
状态：已采纳

## 背景

2026-06 测试报告（333/444）显示 P@10 仅 50%（及格线 60%），首条准确率 50%（及格线 50%，卡线）。失分模式归类：

1. **BM25 单字中毒**：jieba 把"戚风蛋糕"切出单字"戚"，字典站单字释义页拿 BM25 高分
2. **引擎填充噪音**：部分引擎对不匹配查询返回平台导航页/热点新闻（B站首页、36kr 时政）
3. **零相关结果混入 top10**：纯加权混排无硬闸门，垃圾结果靠 recency + trust/reputation 0.5 保底分就能进前排（BM25 仅占 0.15-0.20 权重拦不住）
4. **导航查询 FP**："字节跳动官网"首条是讨论官网的 CSDN 博客

## 决策

排序流水线加三层防线（`relevance_gate.py` + `ranker.py`）：

| 层 | 机制 | 拦截对象 | 成本 |
|---|---|---|---|
| L1 | 覆盖率硬闸门：查询词零命中即丢弃 | 零相关（填充噪音、字典页） | ~0ms |
| L2 | 协调因子：得分 × (0.5+0.5×覆盖率) | 弱相关沉底 | ~0ms |
| L3 | bge-reranker-base 精排 top-20 + sigmoid≥0.25 分数闸门 | 假相关 SEO 页、同义改写真相关重排 | CPU ~0.5-1.5s |

配套规则：
- **热路也过 L1，且门槛 min_coverage=0.5**：回放发现 ES 热路（`HOT_INDEX_ENABLED`）直接返回、完全绕过排序流水线，零相关热点新闻靠 snippet 里的"最新/政策"等泛词就能溜出去（OR 语义闸门拦不住）。热路要求命中至少一半查询词，不足 min_hits 降级 SearXNG。
- CJK 单字 token 不参与 BM25 与覆盖率（修模式 1 的根）
- 导航意图（"官网"类）：根路径 boost +0.15 / UGC 平台惩罚 -0.20（文本相关性区分不了"官网"和"讨论官网的文章"，必须用 URL 形态信号）
- 杀空策略：L1 杀空返回空不回填（零结果率现状 0.01%，余量充足；"搜不到"比"答非所问"对 LLM 调用方有用）；L3 存活 <3 条放弃分数闸门（阈值失准时宁放弱结果不误杀）

## 权衡

**为什么不只靠黑名单/调权重**：黑名单只堵已知坑；调权重无法让 0.15 权重的 BM25 拦住 0.5 保底分的垃圾——需要硬闸门和乘法惩罚改变得分结构。

**为什么 base 不是 v2-m3**：生产机 4c8g 无 GPU，与 SearXNG×3 + Redis 同机。v2-m3（568M）CPU fp32 ~2.3GB 常驻 + 精排 2-4s，内存贴红线；base（278M）~1.1GB + 0.5-1.5s。粗粒度垃圾识别 base 足够；升级只需改一行 `RERANKER_MODEL`。

**词面闸门的盲区**：同义改写（"电脑蓝屏" vs "死机黑屏排查"）覆盖率为 0 会被 L1 误杀——接受此风险，因为标题/摘要与查询完全无词面重叠的中文网页结果占比极小，且 L3 无法在 L1 之前运行（精排 20 条已是 CPU 预算上限，不能精排全集）。

**已知遗留**：导航查询的品牌域名匹配（"Apple Official Website"应返回 apple.com 而非 developer.apple.com）需要 ICP/域名权威数据，单独立项（见 CONTEXT.md 导航意图缺口）。

## 模型分发

hf-mirror.com 在生产网络下 TLS 不稳定（UNEXPECTED_EOF），统一改用 ModelScope 下载到 `models/` 本地目录，`RERANKER_MODEL` 填容器内路径 `/app/models/bge-reranker-base`。

## 验证

`scripts/replay_testset.py` 回放测试集 ~90 query，自动断言已知失分用例（字典页/B站导航页/零相关新闻不得出现在 top10，导航查询 top3 必含目标域名），dump 因子明细对照表供人工 P@10 打标。
